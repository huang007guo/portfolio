# Anthropic 创始人行动手册：打造 AI-Native 创业公司

> 来源：Anthropic 官方手册《The Founder's Playbook》(36页)，由花叔使用 Claude Code 翻译。2026年5月发布。

---

## 概述

AI 正在重塑创业公司的搭建方式。2026年，AI 可以写生产级代码、做市场调研、整理竞争格局、起草投资人材料，并自动化运营流程。学习曲线被抹平，创业者不再受限于"能否写代码"。本手册根据新现实重新梳理创业四个核心阶段——想法、MVP、发布、规模化，并说明如何利用 AI 工具（特别是 Claude）缩短时间线。

---

## 核心原则

- **AI 拆掉了"能造东西的人"和"有想法的人"之间的墙**：非技术创始人能做生产级软件，技术创始人也能轻松产出 GTM 策略、财务模型等
- **创始人角色变化**：从个人贡献者变为 AI agent 的编排者（orchestrator）
- **AI 赋能的三大能力**：
  1. **对话式智能与研究**：充当各领域专家进行深度研究、文档起草、战略思考伙伴
  2. **Agentic 编程**：用自然语言描述需求，AI 生成、测试、调试、重构生产级代码库
  3. **工作流自动化**：自动化排期、CRM 更新、周报汇总、文档同步等重复性运营任务
- **瓶颈不再是你"能造什么"，而是你"选择造什么"**

## 第1章：创业生命周期，为2026重新启动

### 核心变化
- 传统路径：验证 -> 融资 -> 招人 -> 搭建 -> 再融资 -> 增长 -> 再招人（不断循环）
- AI 时代：不再默认每个新阶段都需要更大的团队、不同的技能组合和新一轮融资

### 四个核心阶段
1. **想法阶段**：研究驱动验证
2. **MVP 阶段**：将验证过的问题转化成可运行产品
3. **发布阶段**：把早期势头转化为可重复、可持续的增长引擎
4. **规模化阶段**：从建造者转向面向公众的高管

## 第2章："创始人"这件事正在改变

### 关键转变
- 从个人贡献者变为 AI agent 的编排者
- 注意力转向高阶工作：产生想法，指挥 agent、工具和小团队执行
- 领域专长创业者被解锁：没有工程背景但有行业洞察的人能创办解决传统技术创始人未曾关注问题的公司

### AI 赋能的三大能力

#### 1. 对话式智能与研究
- 充当各领域专家，进行深度研究（竞品分析、市场测算、财务建模）
- 文档起草（BP、PRD）
- 战略思考伙伴（反方论证、情境推演）

#### 2. Agentic 编程
- 用自然语言描述需求，AI 生成、测试、调试、重构生产级代码库
- 堪比完整工程团队

#### 3. 工作流自动化
- 自动化排期、CRM 更新、周报汇总、文档同步等
- 释放创始人时间

## 第3章：想法阶段

### 阶段目标
通过研究导向的验证，在动手开发之前收集扎实证据，证明问题真实存在且方案能解决它。

**需要回答的问题**：问题是否真实、具体、高频？谁有这个问题？市场够大吗？有没有人解决？解决方案需要满足什么？

### 核心指令：先具体，再行动
将模糊的抱怨转化为可测试的假设。例如：
- 模糊："报销很头痛"
- 可测试："中型公司财务经理每周花4小时以上核对报销，因为现有工具不与会计软件打通"

### 退出标准（问题-方案匹配）
对以下三个问题都回答"是"：
1. **问题真实且具体**：能精确描述谁、多频繁、多严重、当前如何处理
2. **方案对应真实问题**：是验证过程中浮现的问题，而非最初假设的问题
3. **有足够信号去实施**：有足够质性证据让投入 MVP 成为有理有据的决定

### 阶段挑战
- **把"造"误当作"验证"**：AI 让建造太容易，42% 创业公司失败是因为造了没人要的东西。原型不是验证证据
- **过早规模化**：执行速度可能远超业务所需，在验证前就锁定错误路径
- **客观性丧失**：AI 会迎合创始人偏见，必须用 AI 反向压力测试想法

### Claude 如何帮助

#### 1. 定义并压力测试问题假设
- 反复打磨问题陈述直到可测试
- 让 Claude 充当反方代言人寻找反证

#### 2. 市场研究与竞争格局梳理
- 分析竞品层级、论证威胁
- 汇总竞品评论找未满足需求
- 构建 TAM/SAM/SOM 模型
- 进行趋势分析

#### 3. 规划并设计客户发现
- 确定访谈对象画像
- 设计访谈问题（避免诱导性）
- 访谈后分析（综合发现、辨识偏见）

#### 4. 客户触达与排期
- 用 Claude Cowork 自动建立名单
- 起草个性化邮件
- 管理日历和跟进

#### 5. 设计最终方案概念
- 用 Claude 挑战方案缺口、替代方案和规模化条件

#### 6. 用 Claude Code 搭轻量原型
- 构建核心交互的功能样本
- 用于用户对话而非真实产品

## 第4章：MVP 阶段

### 阶段目标
将验证过的问题转化成可运行产品，收集关于解决方案的证据，找到产品-市场匹配（PMF）的真实证据。同时避免积累会复利的技术债，并从第一天就建设持久上下文。

### 退出标准
出现 PMF 真实证据：具体、可识别的用户群觉得产品有价值，愿意回头用（留存）、付费（收入）、或推荐他人（推荐）。

### 阶段挑战

#### Agentic 技术债
- 无规格文档和架构约束时，每次会话重新推导决策
- 导致架构漂移、代码库缺乏一致心智模型

#### 误把假 PMF 当真 PMF
- 早期势头（朋友、HN 流量等）不等于 PMF
- 需警惕短暂热度

#### 零摩擦的范围蔓延
- 开发太快，总想加功能
- 需提前定义范围文档，并设置功能修订的证据门槛

#### 因经验不足而不安全
- AI 生成的是功能代码而非安全代码
- 必须在用户接触前进行安全审查

### Claude 如何帮助

#### 1. 动手之前先定架构
- 定义架构决策，保存为 CLAUDE.md 文件
- 作为代码库的持久记忆和开发护栏

#### 2. 定义并执行 MVP 范围
- 写范围文档，明确做什么、不做什么
- 用 Claude 压力测试新功能想法的真实性

#### 3. 用 Claude Code 做 MVP
- 每次会话基于范围文档和 CLAUDE.md
- 结束时更新决策日志
- 保持代码库结构可解释

#### 4. 任何用户上手之前先做安全审查
- 用 Claude 审查认证、数据暴露、输入校验、依赖漏洞
- 必要时用 Claude Code Security（beta）扫描

#### 5. 发布前先把度量框架建好
- 定义指标、基准、PMF 模式与假阳性
- 让 Claude 扮演怀疑者解读数据

#### 6. 管理用户发现和反馈的运营层
- 用 Claude Cowork 管理触达、排期、分诊 bug、汇总周报
- **但真人必须留在反馈解释环里**

#### 7. 朝证据迭代，不是朝"做完"迭代
- **Sean Ellis 测试**：40% 用户说"非常失望"（如果产品消失）为 PMF 指标
- **努力测试**：留存不需要英雄式干预

#### 8. 数据要求 pivot 时就要 pivot
- 若多轮迭代仍无 PMF，让 Claude 诊断:
  - 替代细分市场
  - 价值传达问题
  - 根本性改变

## 第5章：发布阶段

### 阶段目标
把早期势头转化为可重复、可持续的增长引擎，同时加固产品基础设施，围绕产品搭建真正的公司运营系统，消除创始人瓶颈。

### 退出标准
1. **增长可重复、由渠道驱动**：可预测的用户获取，CAC、LTV、回收周期清晰
2. **产品扛得住生产工作负载**：基础设施加固，安全合规到位，可靠性在真实条件下站得住
3. **运营在没有创始人瓶颈下运转**：流程、自动化已就位，创始人不再亲自处理客服、分诊、冲刺规划等

### 阶段挑战
- **技术债到期**：MVP 时期积累的债在生产流量下暴露，需进行架构审查和定向重构
- **创始人成了瓶颈**：从亲自做事转向设计能做完事情的系统
- **安全与合规不能再拖**：真实用户和数据下，漏洞和合规要求成为现实风险
- **还没准备好就扩张**：过早进入差异大的新市场会丢失对数据的清晰解读

### Claude 如何帮助

#### 1. 清算技术债
- 用 Claude Code 跑架构审查，识别弱点
- 排序修复优先级
- 更新 CLAUDE.md 固化决策

#### 2. 搭起替代创始人注意力的系统
- 用 Claude Cowork 审计运营负荷
- 分出三类：可自动化、需委派、需创始人判断
- 设计自动化工作流

#### 3. 把安全与合规做成产品工作流
- 用 Claude Code 扫描代码漏洞和合规缺口
- 用 Claude 设计控制项、审计日志等
- 持续维护合规文档

#### 4. 建立产品管理流程
- 设计冲刺节奏、spec 模板
- bug 分诊树、每周指标简报
- 用 Claude Cowork 运行重复运营环节

## 第6章：规模化阶段

### 阶段目标
从建造者转向面向公众的高管，扩张技术基础设施和组织本身，从几千用户走向几百万，搭建系统化增长，并累积深度建出防御性护城河（专业知识、深度整合、专有数据）。

### 退出标准
公司可持续运转，即使创始人减少日常管理：
- 无需外部资本的规模化盈利
- IPO 就绪
- 或被收购

要求：增长系统化且可审计，产品护城河经得起推敲，组织成熟。

### 阶段挑战
- **把运营层放手出去**：系统需完全可信，创始人需编码并交接机构知识
- **扩张技术运营**：搭建支持基础设施、文档、SLA
- **扩张组织职能**：财务报告、合规监控、合同管理、客户支持等
- **搭一个 GTM 职能**：建立专门的增长引擎

### Claude 如何帮助

#### 1. 把日常任务交给 Claude Cowork
- 绘制瓶颈地图和创始人专属责任清单
- 压力测试现有系统能否随业务扩张
- 修复交接标准

#### 2. 升级技术运营为企业级基础设施
- 起草产品文档、支持 playbook、SLA
- 用 Claude Code 做代码级可靠性与安全加固
- 用 Claude Cowork 运行支持工单、文档更新、续约追踪

#### 3. 搭真正的 GTM 职能
- 用 Claude 构建 GTM 资源（细分、信息架构、sales playbook、投资人叙事）
- 用 Claude Cowork 运行内容管线、联系节奏、报告
- 用 Claude Code 构建产品营销基础设施（demo 环境、集成文档等）

#### 4. 把领域专长转化为 AI 上下文
- 通过长对话和 Projects 捕捉创始人知识
- 用 Skills 编码重复工作流，形成专有知识基底
- 用 Claude Code 把行业边缘情况编码为测试用例，累积护城河

#### 5. 让累积的用户数据复利
- 审计交互数据，识别行为模式
- 设计反馈环
- 起草一页护城河叙事说明数据飞轮优势

#### 6. 制造工作流锁定
- 审计客户工作流集成深度
- 识别锁定最强的集成类型
- 用 Claude Code 搭建更多原生集成、API、webhook
- 使用户不仅使用产品，更在之上开发

## 第7章：工作没变，规则变了

- AI 时代创始人的工作未变：找到真问题，做出解决方案，扩张成有意义公司
- 变化的是路径：
  - 验证周期从月压缩到下午
  - 原型不再需要技术联合创始人
  - 发布从紧张冲刺变为持续工作流
  - 运营重量交给 AI
- **瓶颈不再是你"能造什么"，而是你"选择造什么"**

## 关键反模式警示

| 阶段 | 反模式 | 正确做法 |
|------|--------|----------|
| 想法 | 把"造"误当作"验证" | 先研究验证再开发 |
| 想法 | AI 迎合偏见 | 用 AI 反向压力测试 |
| MVP | Agentic 技术债 | 从第一天就用 CLAUDE.md 固化架构决策 |
| MVP | 把假 PMF 当真 PMF | 用 Sean Ellis 测试（40% 阈值） |
| MVP | 零摩擦范围蔓延 | 提前定义范围文档 |
| MVP | 忽视安全 | 用户接触前必须做安全审查 |
| 发布 | 创始人成瓶颈 | 从亲自做事转向设计系统 |
| 发布 | 技术债到期 | 主动清算而非拖延 |
