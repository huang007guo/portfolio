# 需求分析与任务管理工作流

## 核心原则

当用户提出需求时，必须严格遵循以下三步流程，**不得跳过任何步骤**。

---

## 第一步：需求分析与细化

### 1.1 需求理解
- 仔细阅读用户的需求描述
- 识别需求的核心目标和预期产出
- 标注需求中的模糊点或歧义

### 1.2 需求细化
- 将模糊的需求拆解为可执行的具体任务
- 明确每个任务的输入、输出和验收标准
- 识别技术难点和风险点
- 补充用户未提及但必要的细节

### 1.3 输出格式
需求分析完成后，以结构化方式输出：
```
## 需求分析

### 原始需求
[用户原始描述]

### 细化后的需求
1. [具体任务1]
2. [具体任务2]
...

### 关键问题
- [问题1]
- [问题2]
...

### 技术难点
- [难点1]
- [难点2]
...
```

---

## 第二步：给出建议与指出问题

### 2.1 方案建议
- 提供 2-3 个可行的技术方案
- 说明每个方案的优缺点
- 推荐最适合的方案并说明原因

### 2.2 问题指出
必须明确指出以下问题：
- **需求合理性问题**：需求是否清晰、完整、可行
- **技术可行性问题**：现有技术栈是否能支撑
- **资源评估问题**：时间、人力、成本是否足够
- **风险预警**：可能出现的技术风险、业务风险
- **替代方案**：是否有更简单、更高效的实现方式

### 2.3 输出格式
```
## 建议与问题

### 推荐方案
[方案描述 + 推荐理由]

### 备选方案
1. [方案A]：优点 - 缺点
2. [方案B]：优点 - 缺点

### 存在的问题
- ❌ [问题1]：[具体描述]
- ⚠️ [问题2]：[具体描述]
- 💡 [建议]：[具体建议]

### 风险预警
- [风险1]：[影响 + 应对措施]
- [风险2]：[影响 + 应对措施]
```

---

## 第三步：用户确认后产出需求任务列表文档

### 3.1 触发条件
**只有在用户明确确认需求和方案后**，才能进入此步骤。

### 3.2 需求任务列表文档规范

#### 文档结构
```markdown
# [项目名称] 需求任务列表

## 文档说明
本文档定义了项目的任务分解、依赖关系和执行状态。
**重要规则**：
- 每个任务完成后需附带总结文档（单独文件）
- 一次只能领取一个任务
- 任务状态：待领取 | 开发中 | 测试中 | 已完成

---

## 任务概览

| 任务ID | 任务名称 | 状态 | 依赖任务 | 负责人 | 预计工时 |
|--------|---------|------|---------|--------|---------|
| T001   | [任务1] | 待领取 | 无 | 未分配 | 2h |
| T002   | [任务2] | 待领取 | T001 | 未分配 | 4h |

---

## 任务详情

### T001: [任务名称]
- **状态**：待领取
- **优先级**：高/中/低
- **前置依赖**：无 或 [任务ID列表]
- **可并发任务**：[任务ID列表]（无依赖关系可并行）
- **描述**：[详细说明]
- **验收标准**：
  - [标准1]
  - [标准2]
- **总结文档**：[完成后填写文件路径]

---

## 依赖关系图
[使用 Mermaid 或文字描述任务依赖关系]

示例：
T001 (完成) → T002 (进行中) → T003 (待领取)
            ↘ T004 (待领取)

---

## 并发任务说明
以下任务组合可以并发执行（无依赖关系）：
- T001 和 T003
- T002 和 T004（需 T001 完成后）

---

## 任务状态说明
- **待领取**：任务已定义，等待分配
- **开发中**：任务已领取，正在开发
- **测试中**：开发完成，等待测试
- **已完成**：测试通过，任务完成

---

## 任务领取规则
1. ⚠️ **一次只能领取一个任务**
2. 领取任务后，状态从"待领取"变为"开发中"
3. 完成任务并编写总结文档后，状态变为"测试中"
4. 测试通过后，状态变为"已完成"
5. 只有"已完成"任务的依赖任务才能被领取

---

## 总结文档规范
每个任务完成后，必须创建总结文档，包含：
1. **任务目标**：实现了什么
2. **技术方案**：使用了什么技术/方法
3. **关键代码/配置**：核心实现（引用文件路径）
4. **遇到的问题**：遇到了什么问题，如何解决的
5. **经验总结**：可以复用的经验或注意事项
6. **输出物**：产生的文件/代码/文档列表

总结文档命名：`task_[任务ID]_summary.md`
存放位置：`.codebuddy/task-summaries/`
```

### 3.3 任务分解原则

#### 依赖关系识别
- **强依赖**：任务B必须等待任务A完成后才能开始
- **弱依赖**：任务B可以在任务A部分完成后开始（如接口定义完成即可开始前端开发）
- **无依赖**：任务可以独立进行

#### 并发任务识别
- 识别所有无依赖关系的任务
- 识别所有弱依赖任务（可提前启动）
- 明确标注哪些任务可以并行

#### 任务粒度控制
- 单个任务时长控制在 0.5-8 小时
- 每个任务应该有明确的产出物
- 避免任务过大难以追踪进度

---

## 执行流程总结

```
用户提出需求
    ↓
第一步：分析需求，细化需求
    ↓
输出：需求分析报告
    ↓
第二步：给出建议，指出问题
    ↓
输出：方案建议与问题清单
    ↓
等待用户确认 ☑️
    ↓
第三步：产出需求任务列表文档
    ↓
输出：[项目名]_task_list.md
    ↓
开始执行（按任务列表进行）
```

---

## 禁止行为

❌ **严禁**在用户提出需求后立即开始编码
❌ **严禁**跳过需求分析和方案建议步骤
❌ **严禁**在未得到用户确认前创建任务列表
❌ **严禁**同时领取多个任务
❌ **严禁**任务完成后不写总结文档

---

## 提醒语句

在每一步完成时，使用以下提醒语句：

**第一步完成后**：
> 需求分析已完成，请查看上方的分析内容。如有需要补充或调整的地方，请告诉我。如无疑问，我将进入第二步：给出建议与指出问题。

**第二步完成后**：
> 方案建议和问题分析已完成，请查看上方的建议内容。如同意推荐方案，请明确确认，我将为你生成详细的需求任务列表文档。

**第三步完成后**：
> 需求任务列表文档已生成：`.codebuddy/task-summaries/[项目名]_task_list.md`
> 
> **接下来你可以**：
> 1. 查看任务列表，确认任务分解是否合理
> 2. 领取第一个任务（状态改为"开发中"）
> 3. 我开始执行，完成后会生成总结文档

---

## 示例对话流程

**用户**：我想做一个用户登录功能

**助手**：
【第一步：需求分析与细化】
```
## 需求分析

### 原始需求
用户登录功能

### 细化后的需求
1. 前端登录页面设计与实现
2. 后端登录接口开发（账号密码验证）
3. 登录状态管理（Token/Session）
4. 登录失败处理（错误提示、限流）
5. 安全性增强（密码加密、防暴力破解）

### 关键问题
- 使用 Token 还是 Session？
- 是否需要第三方登录（微信、GitHub）？
- 密码加密方式（bcrypt / Argon2）？

### 技术难点
- 状态管理的选择（JWT vs Session）
- 安全防护（CSRF、XSS、暴力破解）
```

【等待用户反馈】

**用户**：分析得不错，继续

**助手**：
【第二步：给出建议与指出问题】
```
## 建议与问题

### 推荐方案
使用 JWT Token + bcrypt 加密
理由：无状态、适合前后端分离、安全性高

### 存在的问题
- ❌ 需求未明确：是否需要"记住我"功能？
- ❌ 需求未明确：登录失败几次后需要验证码？
- ⚠️ 建议：增加"忘记密码"功能
- 💡 建议：使用 Redis 存储 Token 实现单点登录控制

### 风险预警
- 密码明文传输风险：建议使用 HTTPS + 前端加密
- Token 泄露风险：建议设置短过期时间 + 刷新机制
```

【等待用户确认】

**用户**：确认，按推荐方案来

**助手**：
【第三步：生成任务列表文档】
```
已生成需求任务列表文档：.codebuddy/task-summaries/user-login_task_list.md

任务概览：
- T001: 数据库设计（待领取）→ 无依赖
- T002: 后端接口开发（待领取）→ 依赖 T001
- T003: 前端页面开发（待领取）→ 可并发 T002
- T004: 登录状态管理（待领取）→ 依赖 T002, T003
- T005: 安全增强（待领取）→ 依赖 T004

请确认任务列表，然后可以开始领取任务。
```
