## 1. Windows PowerShell 脚本中文编码规范

### 问题
Windows PowerShell 5.1 右键运行 .ps1 文件时，默认用系统 ANSI 编码（中文系统为 GBK）解析脚本文件。UTF-8 无 BOM 的 .ps1 文件中，中文字符会被错误解析为 GBK，导致乱码、字符串引号/方括号等语法被破坏，出现"数组索引表达式丢失或无效"、"字符串缺少终止符"等错误。

### 解决方案：保存为 UTF-8 BOM 编码

#### 方法一：使用 PowerShell 写入（推荐，CodeBuddy 可用）
```powershell
# 单引号 here-string 保留内容原样，Out-File -Encoding utf8BOM 写入
$f = "path/to/script.ps1"; @'
# -*- coding: utf-8 -*-
Write-Host "[中文消息] 测试..."
'@ | Out-File -FilePath $f -Encoding utf8BOM
```

#### 方法二：使用 .NET 方法
```powershell
$utf8Bom = [System.Text.UTF8Encoding]::new($true)
[System.IO.File]::WriteAllText("path/to/script.ps1", $content, $utf8Bom)
```

#### 方法三：手动加 BOM（已有 UTF-8 文件）
```powershell
# 读取全文，前置 BOM 字节，写回（注意：是前置，不能 Skip）
$bom = [System.Text.UTF8Encoding]::new($true).GetPreamble()  # EF BB BF
$all = [System.IO.File]::ReadAllBytes($f)
[System.IO.File]::WriteAllBytes($f, $bom + $all)
```

### 注意事项
- CodeBuddy 的 `write_to_file` 工具写入的是 UTF-8 无 BOM，需要后续用上述方法添加 BOM
- `execute_command` 中的 here-string 必须用单引号 `@'...'@`（`@` 后无空格），不能用双引号版本
- 验证 BOM：`[System.IO.File]::ReadAllBytes($f)[0..2]` 应为 `EF BB BF`
- `# -*- coding: utf-8 -*-` 声明本身对 PowerShell 无效，但可保留作为编辑器提示

## 2. FFmpeg CUDA 硬件加速规范

运行 FFmpeg 时，如果系统支持 CUDA 硬件加速，优先使用 CUDA 加速命令。

### 主要用法
1. 使用 `-hwaccel cuda` 启用 CUDA 硬件解码加速
2. 使用 `-hwaccel_output_format cuda` 将解码后的帧保留在 GPU 内存中
3. 使用 NVIDIA 硬件编码器：`-c:v h264_nvenc`（H.264）或 `-c:v hevc_nvenc`（HEVC/H.265）
4. 示例命令：`ffmpeg -hwaccel cuda -i input.mp4 -c:v h264_nvenc -preset p4 output.mp4`
5. 可用 `ffmpeg -hwaccels` 查看支持的硬件加速方式

## 5. CodeBuddy 规则系统说明

CodeBuddy 支持两种规则类型：

### 5.1 项目规则（Project Rules）
- **存储位置**：代码库的 `.codebuddy/rules/` 目录下
- **目录结构**：每条规则对应一个包含 `RULE.mdc` 文件的文件夹（例如 `.codebuddy/rules/my-rule/RULE.mdc`）
- **版本控制**：纳入版本控制，可与团队成员共享
- **文件格式**：Markdown + YAML 元数据头
- **元数据字段**：
  - `description`: 规则描述，供 AI 判断是否加载
  - `alwaysApply`: true = "总是"类型（每个会话自动加载）；false = "智能体请求"类型（按相关性自动加载）
  - `enabled`: true/false，控制规则是否启用
  - `updatedAt`: 更新时间戳（ISO 8601 格式）
  - `provider`: 提供者信息
- **应用类型**：
  - 总是（always）：`alwaysApply: true`，每个聊天会话自动加载
  - 智能体请求（requested）：`alwaysApply: false`，Agent 根据描述判断相关性后自动加载
  - 手动（manual）：在对话中被 @ 提及时加载（例如 `@my-rule`）

### 5.2 用户规则（User Rules）
- **存储位置**：本机用户目录中（不会被版本控制跟踪）
- **作用范围**：本地 CodeBuddy IDE 中全局生效，跨所有项目使用
- **适用场景**：定义个人编码偏好和工作习惯
- **文件格式**：与项目规则相同（Markdown + YAML 元数据头）

### 5.3 重要注意事项
1. 规则只会添加到每个会话的开始部分
2. 创建或修改规则后，需要新建对话会话才能让规则生效
3. 当前会话不会自动加载新增或更新的规则
4. 规则建议控制在 500 行以内，较大的规则拆分为多个可组合的规则

### 5.4 CODEBUDDY.md 补充
- 项目根目录中的 `CODEBUDDY.md` 会被默认将原文全文放入上下文
- 无元数据或复杂配置，适合简单项目
- 向后兼容：存在 `AGENTS.md` 而不存在 `CODEBUDDY.md` 时，自动加载 `AGENTS.md`

## 6. Python 脚本编写规范（Windows PowerShell 兼容性）

### 6.1 字符串和输出规范
1. **禁止在字符串中使用 emoji 字符**（Windows PowerShell 不支持，会导致编码错误）
2. **避免特殊 Unicode 字符**：如箭头(→←↑↓)、特殊符号(★☆◆◇)等
3. **输出信息使用纯 ASCII 字符**：字母、数字、标准标点符号
4. **日志和打印语句**：使用简单文本，避免装饰性字符

### 6.2 文件编码规范
5. **Python 文件编码**：文件头部添加 `# -*- coding: utf-8 -*-`
6. **读写文件时明确指定编码**：使用 `open(file, encoding='utf-8')`
7. **CSV/JSON 等操作**：始终指定 `encoding='utf-8'`

### 6.3 Windows 兼容性建议
8. **避免使用 Windows 命令行特殊字符**：如 `& | < >` 等需要转义的字符
9. **路径使用原始字符串或双反斜杠**：`r"C:\path"` 或 `"C:\\path"`
10. **打印中文时**：确保控制台支持 UTF-8，或提供降级方案

### 6.4 错误示例
❌ `print("✅ 成功!")`  # emoji 会导致 PowerShell 报错
❌ `print("→ 下一步")`  # 特殊箭头字符可能乱码
❌ `open(file)`  # 未指定编码，Windows 下可能出错

### 6.5 正确示例
✅ `print("[成功] 任务完成")`
✅ `print("-> 下一步")`
✅ `open(file, encoding='utf-8')`
